# Baseline source audit and adapter contract

Audited source revisions:

- ZeroED: `49678b8470180ab17e9c40bcedd2c00ac49de6ff` from <https://github.com/WelkinNi/ZeroED>.
- ZeroEC: `d76ef45509d7e0f9e7cc0fa98d445c06afbb157c` from <https://github.com/YangChen32768/ZeroEC>.

This audit read program sources, configuration, prompt templates, dependency manifests, and directory/file names. It did **not** read clean/reference CSVs, supplied perfect-detection CSVs, or computed evaluation results. No cached benchmark LLM results were reused.

## ZeroED algorithm implemented by the upstream source

`main.py` computes normalized mutual information from dirty data to select the top two related columns. It generates preliminary clean predicates from up to 20 random dirty rows per column. `feature.py` builds co-occurrence counts, three string pattern frequencies, fastText vectors reduced to the column count, and preliminary predicate outputs. Its default representative method is named `RANDOM`: a fixed NumPy seed of zero selects 5% of rows, capped by the number of distinct target/related tuples, and every row is assigned to its nearest representative in feature space.

Separate LLM calls generate executable distribution-analysis functions, column guidelines, and JSON error labels for batches of 20 representatives. Representative labels are propagated to the associated clusters. Further LLM calls generate error-conditioned predicates and synthetic errors. The code filters predicates and pseudo-clean labels using a 50% acceptance condition. Per-column `MLPClassifier` models use hidden layers `(2d, d)`, Adam, ReLU, `random_state=42`, `n_iter_no_change=10`, and `max_iter=5000`; their binary predictions form the detection result.

The wrapper exposes each trained classifier's uncalibrated `predict_proba` estimate for pseudo-label class 1 so the core loop can inspect uncertainty, including the requested interval `[0.25, 0.85]`. A prediction-only observer receives exactly the feature matrix constructed by upstream `make_predictions`, returns the original `model.predict` decisions without modification, and separately captures class-1 scores. Metadata stores the original boolean matrix in `upstream_binary_decisions`, with `decision_threshold=0.5` and `decision_threshold_operator=">"`. The strict inequality matters: exactly 0.5 predicts clean in scikit-learn. Every observed column is checked against this relation. A one-class fitted model receives constant 0 or 1 scores matching its sole pseudo-label; a column with no training features retains upstream's all-clean decisions and zero scores. This exposes existing classifier outputs without changing training or source standalone detection. Sequential ZeroEC consumes and validates the stored source mask; the core loop consumes continuous scores.

The committed source has an important all-clean-representative edge case. `gen_err_funcs` returns no conditioned predicates when there are no error-labeled representatives. Its subsequent pseudo-clean filter then removes every clean training row because the accepted fraction is `0/(0+1e-6)<0.5`. If synthetic errors were generated, only label-1 examples remain and the source MLP fits a single class, predicting error everywhere in that column. This is preserved source behavior, not a boolean convention reversal. A synthetic regression executes the actual representative parser, empty conditioned-function path, committed filter loop and training-label builder to demonstrate the trace. Per-column metadata records representative/training label counts, clean counts before/after filtering, predicate count and the identified edge case. No reference labels or evaluation results inform it. The driver re-execs with `PYTHONHASHSEED=0`; metadata records the actual `python_hash_seed` alongside Python/NumPy's explicit seed.

The main entrypoint loads the clean table, computes `gt_wrong_dict`, and runs intermediate/final evaluation. Those values are not needed by the model stages. `label_prop` accepts clean/dirty paths but never reads either path. The extraction runner omits the main entrypoint, `measure_llm_label`, and clean-aware `process_related_attr` entirely, computing the same related attributes directly from dirty data instead.

Current source issues and dependencies:

- `main.py` imports `guide_gen_prompt`, whereas `prompt_gen.py` defines `kb_gen_prompt`. The extraction runner explicitly aliases these names and records the repair.
- `feature.py` hardcodes `./data/<dataset>_error-01.csv` and `./cc.en.300.bin`. The runner creates an isolated source-work directory containing only its dirty input and a link to the specified original model.
- The original `cc.en.300.bin` must be supplied separately. The environment now has `fasttext` and `tqdm`; preflight reports whether the original checkpoint is available. No substitute embedding is permitted on the source ZeroED path.
- There are no published ZeroED result-cache directories in this checkout. `run_config.yaml` has all replay flags enabled and references unavailable historical result paths. Fresh dirty-only LLM responses are required.
- The source leaves random sampling unseeded at several stages. The wrapper seeds Python/NumPy and schedules independent attribute stages sequentially. It retains upstream function bodies, representative/MLP settings, generated-error parsing, and filtering behavior.
- The wrapper does not import unused `torch`, `sentence_transformers`, `openai`, or `kneed` dependencies; it supplies only modules actually used by the extracted algorithm.
- Predicate evaluation shares one reentrant cache lock across upstream's feature workers. The initial batch primes both actual source parser views: `main.py` uses `dtype=str`, while `feature.py` infers numeric types before `astype(str)`, so `"12"` and `"12.0"` remain distinct values with their own predicate outputs. Concurrent workers share the first fill. A newly encountered tuple extends the cache using only previously unseen normalized records; a pending synthetic batch is evaluated once per rule/key shape, without rerunning old rows. Synthetic tests verify mixed numeric representations, one shared fill across 16 workers, and 20 single-row extensions instead of 20 repeated full-table batches.

Supported predicate runtime failures preserve native upstream `handle_func_exec` behavior: a missing-key `KeyError` or invalid-value `ValueError` remains `-1` and is recorded in `sandbox_predicate_runtime_errors`, even if all evaluated rows fail. These errors alone do not imply an adaptation. One shared executor invocation returns both outputs and diagnostics, distinguishing such failures from invalid syntax/policy, timeouts, unavailable confinement, resource/environment errors, or outer execution failures; those remain fidelity rejections. Upstream sometimes passes an outer target attribute absent from a related tuple, so only this source adapter disables the shared executor's nonsemantic target-presence metadata precheck. AST validation and OS confinement remain active; default validation for other callers is unchanged. A predicate that ignores the absent attr may still succeed exactly as native source would.

Old clustering caches undergo a predicate-only compatibility check under the corrected execution contract, without loading fastText. The wrapper recomputes raw preliminary-predicate columns and compares their independently MinMax-scaled geometry. If geometry is unchanged, including a constant `-1` becoming a constant `1` (both scale to zero), it updates raw features and provenance while retaining clustering. A genuine normalized feature change triggers source reclustering. New caches preserve the predicate contract and policy/runtime diagnostics, which are restored on replay so prior fidelity evidence cannot disappear. Metadata records the compatibility decision and cache evaluation counts.

`prepare_fasttext_dimensions(original_path, output_dir, dimensions=(6,9,11,17,22))` prepares each required reduction sequentially from the original checkpoint. The CLI is `.venv/bin/python scripts/prepare_fasttext_dimensions.py --original artifacts/models/cc.en.300.bin --output artifacts/models/reduced`. Ordinary `fasttext.util.reduce_model` holds a full C++ model plus matrix copies; this helper instead validates the unquantized v12 binary layout and memory-maps original matrices read-only. Its PCA copies the upstream first-100000-row float32 mean/covariance and `np.linalg.eig` lines exactly, preserving the unsorted basis and final float32 casts. Every dimension starts from original matrices, never another reduced checkpoint, and consumes no NumPy RNG.

The actual official checkpoint's PCA returns `complex64` eigenvectors, even though the observed imaginary maximum is zero. Passing the whole float32 input to complex matrix multiplication promotes the full several-GB matrix and caused measured memory/swap pressure in the first preparation attempt. The replacement streams projection in 8192-row blocks, immediately casts/writes each narrow result, and advises the OS to release clean mapped source pages with `MADV_DONTNEED` when available. Neither a full complex input nor a full reduced pair is retained. Real float32 projections retain full-shape GEMM, because row-blocking real OpenBLAS GEMM can change final rounding bits; this branch has no full complex input promotion. Progress and manifest entries record projection dtype, and provenance identifies `upstream_pca_complex_row_blocks_real_full_matmul_v2`, the upstream reduction source hash, and the bounded execution hash. Tests use 16421×300 inputs, noncontiguous `U[:,:d]` layouts, real/complex projections and all five dimensions; their final float32 bytes equal `_reduce_matrix`. Saved fastText files with 9009 input rows also match upstream output byte for byte.

Prepared files and their manifest are made read-only and installed atomically under a lock. The manifest records original/reduced/projection SHA256s, the reduction-function source hash, NumPy and fastText versions, and dimensions. Reuse verifies identity and cached bytes; preflight rechecks a selected prepared model's hash, and the source runner rejects a prepared dimension that differs from the table's column count. The source-work symlink is refreshed when a run switches from the original to its prepared reduction. The runtime skips a second PCA when a checkpoint already has the required dimension. Synthetic checks compare all five prepared files byte for byte against `fasttext.util.reduce_model` plus `save_model`, verify identical word vectors/matrices and unchanged RNG, and reject modified cached bytes.

## ZeroEC zero-shot path

`correction.py` uses representative human repairs obtained from `clean_data`, then generates dataset-specific examples and correction code/functional dependencies. This entrypoint is excluded from a strict dirty-only experiment.

`correction_zero_shot.py` comments out those human-repair/code/FD stages. It embeds cells using `all-MiniLM-L6-v2` through `FastSentenceTransformer`, chooses related columns by dirty-data mutual information (normalized/rounded score at least 0.5), builds a FAISS index over concatenated cell embeddings, retrieves 30 rows, sorts using retrieval score and detection indicators, and supplies three rows to an LLM for each detected cell. For the dataset string `imdb`, retrieval context is disabled in the source. The prompt also includes fixed general correction examples. Those examples are few-shot guidance; they require explicit policy treatment if zero-shot is intended to forbid any example answers, including examples outside the six benchmark tables.

The bundled MiniLM checkpoint **is present** at `vendor/ZeroEC/all-MiniLM-L6-v2`. However, the exact zero-shot entrypoint refers to three template filenames absent from the checkout: `SystemMessage_EC.txt`, `HumanMessage_EC.txt`, and `general_examples_EC.txt`. Other templates are present but are not automatically substituted, since this would change the baseline. Required LangChain/FAISS/FastSentenceTransformer modules are also absent, and the source embedding wrapper assumes CUDA devices 0–3. The main entrypoint additionally loads clean data for final evaluation; an inference wrapper must omit it. `repair_value` assumes an `index` data column for logging, another portability defect to address explicitly.

No completed exact ZeroEC execution or reproduction is claimed. `preflight_zeroec` reports source/runtime/template blockers. Its separate `reconstruction` field reports readiness for the explicitly named reconstruction below; it never changes exact-path readiness.

## Explicit source-derived ZeroEC reconstruction

`run_reconstructed_zeroed_zeroec` implements the committed zero-shot correction path using **only source ZeroED predictions** for detection. Its output is named `zeroed_zeroec_reconstruction`, with `fidelity=source_derived_reconstruction` and `reproduced_upstream=false`. It is not an exact ZeroED→ZeroEC baseline result and must retain that qualifier in comparisons. The original exact ZeroEC path remains unavailable because its three named prompt files were never committed.

The reconstruction retains the source MI calculation (including repeated-pair filtering), normalization and one-decimal rounding, related-column threshold 0.5, concatenated cell embeddings, detection masking, MI query weights, 30-row retrieval, two-decimal score rounding, detection-aware sorting, three-row context, and one LLM correction per detected cell. The `imdb` dataset string disables context exactly as upstream; the distinct benchmark name `movies` does not trigger this branch. Retrieved rows contain only fields predicted clean by ZeroED, not verified clean values. The detection matrix remains unchanged and correction results never feed back into detection or later correction prompts.

The bundled `quantized_true.onnx` is the exact filename loaded by `fast_sentence_transformers==0.4.1` with `quantize=True`. The dependency's published wheel source was inspected without installation. Its `encode_batch` explicitly uses `max_length=512`, overriding the checkpoint's 256-token sentence configuration, followed by masked mean pooling. The reconstruction uses that bundled graph with ONNX Runtime CPU, the committed tokenizer, batch size 64, the same decreasing-length ordering, masked mean pooling, and L2 normalization. CPU execution may differ numerically from upstream CUDA. Dirty-derived embedding caches are fingerprinted by dirty input, checkpoint/tokenizer/pooling hashes, encoder configuration, token limit, and batch size; no published result cache is reused.

An additional source issue affects retrieval: ZeroEC passes `DistanceStrategy.DOT_PRODUCT`, but `langchain-community==0.0.28` creates `IndexFlatIP` **only** for `MAX_INNER_PRODUCT`; all other strategies, including `DOT_PRODUCT`, create `IndexFlatL2`. This was verified in the pinned dependency's published wheel. The reconstruction therefore calculates squared L2 distance in NumPy using vector norms and dot products, with normalized individual cell embeddings but without renormalizing concatenated rows or weighted queries. The 30 nearest rows are retained before upstream sorting by ascending rounded distance, target-column detection, and related-column error count. Exact ties use stable row order; backend float32 arithmetic can affect near-ties. Treating the configured enum as a true inner-product index would change the algorithm.

Prompt substitutions are explicit and included in each request's source hashes. The committed `SystemMessage.txt` and `HumanMessage.txt` replace absent `SystemMessage_EC.txt` and `HumanMessage_EC.txt`. Their `specific_examples` placeholder is left blank, matching the absent-template entrypoint's blank `dataset_specific_examples`. Manual JSON schema instructions replace LangChain parser-format text, and system/human text is serialized through the existing explicit callback. By default, committed `examples.txt` replaces missing `general_examples_EC.txt`, and metadata declares `strict_zero_shot=false`. Set `use_general_examples=False` to omit those fixed answer examples under a stricter zero-example policy; this additional prompt change is recorded. Neither choice can be reported as an exact reproduction. The upstream logging-only `index` column requirement is removed, using row positions instead.

An explicit alternative `prompt_profile="author_zerodc_29cde9e0dbcd"` selects the verbatim EC prompt candidates recovered from the same author's ZeroDC repository at commit `29cde9e0dbcdde04c34bbc4c185c73b357817390`. The default profile remains `committed_zeroec`; no missing-file fallback or automatic protocol switch occurs. The recovered system message differs from the committed ZeroEC message and includes the expected `dataset_specific_examples` placeholder. Its historical identity to the omitted pinned ZeroEC prompt remains unproven, so output remains a reconstruction with `fidelity="author_source_reconstruction"` and `reproduced_upstream=false`. See [the recovery audit](zeroec_prompt_recovery.md) for primary-source evidence and the precise limitation.

The author profile pins all three recovered filenames and their audited SHA256s in code, verifies selected prompt bytes and the saved provenance manifest's repository/revision/hash claims, and repeats validation when loading templates. Missing, altered, or unrecognized profiles fail closed. The runtime never copies these files into the vendor checkout. Requests and results carry the selected `prompt_profile`, prompt hashes, author repository/commit, audit-manifest hash and `historical_identity_established=false`. Select `use_general_examples=False` for this experiment's strict policy: neither recovered nor committed fixed examples are loaded into the prompt, and dataset-specific examples remain blank. Its default recovered directory is `artifacts/recovered_prompts/zerodc_29cde9e0dbcd`; `recovered_prompt_dir` can locate the same hash-bound artifacts elsewhere. Synthetic tests verify explicit profile selection, zero-example rendering, author provenance and rejection of prompt/manifest tampering without fallback.

Each cell's request contains its dirty fingerprint, detector score hash, selected retrieved row indices, source/prompt/checkpoint hashes, reconstruction label, and retry number. All independent detected cells are enqueued before a `ResponsePending` is raised. Up to three separately addressed JSON-parsing attempts match the source's retry budget; after three invalid replies the cell stays unchanged and errors are recorded. Replays reuse only responses to matching requests. `queue_status.json`, `preflight.json`, `metadata.json`, and completed `prediction.json` are reviewable outputs. No clean-table loader, supplied detection mask, human repair stage, code/FD generation, or evaluation function is imported or run.

ZeroEC's source dataframe represents missing values internally as the string `null`; the harness preserves raw CSV strings. The reversible export adapter therefore keeps the original raw text whenever a parsed correction equals that cell's source-internal value. For example, original `""` or `"NA"` parsed as internal `null` and returned unchanged produces no repair. A newly introduced missing value, including JSON `null`, exports as an empty CSV cell. This prevents normalization alone from fabricating `""→"null"` corrections and requires no labels. Metadata records this rule in `null_sentinel_policy`. Correction replies must explicitly contain the requested column and a finite scalar string, number, or null; malformed replies enter the declared retry path.

`SourceCTS` is the shared retrieval implementation used directly by this naive correction runner and available to the core loop's repair-proposal stage. Construct it with `(table, detection, output_dir, source_dir="vendor/ZeroEC", embedding_path=None, exclude_query_row=False, max_cached_columns=None)`. Detection accepts a source `Prediction`, a boolean mask, or a probability matrix; uncertainty-only inputs are supported, and supplied source masks are validated against strict `p>0.5`. The dirty-derived embedding matrix is cached by its existing input/model identity and reopened as a read-only memory map. Per-target MI, concatenated vectors/norms, error counts, and filtered tuple documents are cached when used.

The optional positive integer `max_cached_columns` bounds per-column state using least-recently-used eviction; the default `None` retains the unbounded API. Eviction releases an old state before allocating the next concatenated matrix and leaves the shared cell embedding map unchanged. The sequential correction runner uses a two-column cache and its existing column-grouped traversal. Recomputed state uses the identical source calculation, and cache policy is deliberately absent from context provenance and request metadata: complete returned context JSON, prompts, response identities, numerical ranking and repairs remain unchanged. Synthetic tests compare bounded and unbounded retrieval across repeated evictions and compare every sequential request and final repair.

Shared embedding creation and validation are protected by an `fcntl` process lock. New `.npy` data is written/fsynced through a unique temporary file, atomically installed under its dirty/model cache key and made read-only, then committed by an atomic metadata pointer. Existing mapped readers retain their original inode when a different key publishes. A crash after matrix publication but before metadata commit can be recovered without re-encoding. Existing legacy `embeddings.npy` caches remain readable under the lock. A four-process mock-encoder regression verifies one creation, identical read-only readers and unchanged held mappings across replacement; another regression verifies interrupted metadata publication recovery.

`cts.retrieve(row, column, k=3)` returns source-ranked `selected` rows (index, rounded score, detection indicators, document and filtered tuple), `tuples`, retrieved row `indices`, related-column indices/names and MI `weights`, the exact baseline prompt `context` and `query_tuple_text`, plus dirty/detector/source/checkpoint provenance. The baseline retains original self inclusion. The core loop can construct `SourceCTS(..., exclude_query_row=True)`; this removes the query row before the nearest-30 cap and records that deliberate loop-only change. Predicted-dirty fields remain excluded from context in both paths, and the source `imdb` exception is preserved. Fixed synthetic embeddings verify equivalence to the prior retrieval formula and source ranking, as well as cached column reuse, uncertainty-only retrieval, and self exclusion. Sequential output also propagates `upstream_binary_decisions`, `decision_threshold=0.5` and `decision_threshold_operator=">"` at the top level for exact standalone evaluation.

The optional per-call `mask_query_target=True` zeros only the target column's query embedding even when its detector score is uncertain. Other globally detected query fields remain masked, while other uncertain fields retain their embeddings. Stored peer documents and their original detector masks remain unchanged; neither predictions nor the shared embedding matrix are mutated. This is an explicit loop policy, not the default source baseline. The default `False` preserves the complete prior returned context JSON and omits the new provenance field entirely, protecting active request identities. Only `True` adds `mask_query_target:true` to returned provenance. A synthetic ranking/query test verifies target-only masking, retained uncertain context, unchanged peer masks and byte-equivalent default rendering. Changing an active queuer's mask policy requires a separately versioned/requeued protocol.

Dependency source references: [fast-sentence-transformers 0.4.1](https://pypi.org/project/fast-sentence-transformers/0.4.1/) and [langchain-community 0.0.28](https://pypi.org/project/langchain-community/0.0.28/).

## Public adapter API

- `preflight_zeroed(source_dir="vendor/ZeroED", fasttext_path=None) -> dict` reports resources, source hashes, and the import-alias repair without touching datasets.
- `run_exact_zeroed(table, request, output_dir, fasttext_path=None, source_dir="vendor/ZeroED", seed=42) -> Prediction` writes a preflight artifact and fails closed with `BaselineUnavailable` when original resources are missing. The callback is `request(stage: str, prompt: str, metadata: dict) -> str`; `FileLLMQueue.request` satisfies this interface. Pending responses propagate; no fake response is provided.
- `preflight_zeroec(source_dir="vendor/ZeroEC", embedding_path=None) -> dict` reports the exact zero-shot path's blockers. The bundled checkpoint is discovered automatically.
- `run_reconstructed_zeroed_zeroec(table, detection, request, output_dir, source_dir="vendor/ZeroEC", embedding_path=None, use_general_examples=True, prompt_profile="committed_zeroec", recovered_prompt_dir=None) -> Prediction` runs the explicitly labeled reconstruction described above and rejects `adapted_zeroed` detection. It preserves detection probabilities, ignores any prior detector repairs, and proposes corrections only for source ZeroED detections at threshold 0.5. The callback matches `FileLLMQueue.request`. The `use_general_examples=False` setting omits fixed example answers and records that additional deviation. Explicit `prompt_profile="author_zerodc_29cde9e0dbcd"` uses hash-bound author candidates with their unresolved historical-identity limitation.
- `queue_zeroed_preliminary(table, request, output_dir, source_dir="vendor/ZeroED", seed=42) -> dict` prepares every column's original preliminary-function request before the fastText model is available, with identical request identities for later source-run replay. It executes no generated source.
- `adapted_zeroed(table, artifacts=None, seed=42, max_iter=500) -> Prediction` is an executable, single-pass, **source-informed adaptation**, not a reproduced baseline. It evaluates pass-1 dirty-only LLM predicates, labels 5% random representatives from rule hits, propagates to nearest character/frequency features, and fits an upstream-shaped MLP. Hashing replaces fastText; it omits separate guideline/distribution/label prompts, synthetic errors, and the three upstream predicate filters. All changes are included in prediction metadata.
- `adapted_zeroed_zeroec(table, detection, artifacts=None) -> Prediction` applies pass-1 dirty-only value proposals only to detected cells. It does not reproduce MiniLM/FAISS retrieval or per-cell ZeroEC prompts; the metadata declares that substitution. It uses no second-pass rules or feedback.

`table` has only the dirty table name, column names, immutable string rows, and dirty input fingerprint. `Prediction` has an `n × m` probability matrix, sparse `(row, column) -> replacement` mapping, and metadata. The source ZeroED wrapper now returns uncalibrated classifier scores and preserves original binary decisions in metadata, as described above.

Pass-1 artifacts use `rules:[{id,target,kind,source,description}]`, where sandboxed `check(row)` returns true for dirty, and optional `value_repairs:{column:{old_value:new_value}}`/`repairs:[{row,column,value}]`. The adapted path does not consume second-pass artifacts or discovered FD metadata. It records input/artifact hashes, source hashes, fidelity status, and changed settings. Output names must retain the `adapted_` prefix in tables and reports.
