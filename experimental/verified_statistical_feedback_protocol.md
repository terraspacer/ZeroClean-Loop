# Preregistered verified statistical feedback, version 1

This protocol is fixed before implementation tests or evaluation. It defines a separate, unpromoted processor of frozen v3 statistical feedback or v4 detection feedback and independent verification. It neither refits models nor uses benchmark labels, error rates, outcomes, or the standard closed loop. Thresholds and actions are uniform across datasets. Existing statistical artifacts and source-loop predictions remain immutable.

## Inputs and independent review

Inputs are the exact source-loop prior, frozen v3 correction prediction, original dirty table, executable-rule artifact, frozen v3/v4 verification bundle and its output/final manifest. Preparation checks fingerprints, manifest byte binding, bundle content hash, recorded prior/v3/artifact provenance, coordinates, originals, prior/tentative tuples, intervals, and frozen-map agreement. It writes a separate content-hashed request binding all input and implementation hashes and this protocol. V4 original_tuple is copied into the generic verifier's tuple field; its only additional repair choices come from frozen v3 and exact prior fallback. No live posterior contexts are reconstructed or model fits changed.

Every queued cell discloses all frozen semantic contracts and otherwise-hidden header fields, conditional-weight interpretation, source/entity hypotheses, original/prior/statistical tuples, and evidence. The verifier must return every requested cell and every exact candidate, the usual bounded original_valid_score, confidence, selected_value and candidate scores, plus statistical_evidence_decision and accepted_semantic_contract_hashes. The decision is one of accept_original_valid, accept_original_invalid, reject, ambiguous. Accepting a statistical conclusion requires explicit acceptance of BOTH target-attribute source contracts by their exact hashes. Empty/missing contract acceptance means abstention, never implicit support. These are fallible semantic judgments, not observed truth.

## Detection and correction

The immutable source prior is the fallback. Detection threshold is 0.5. Verifier confidence must be at least 0.8, its directional original score must be strictly above 0.5 for valid or below 0.5 for invalid, and the explicit statistical decision must agree with eligible frozen statistical evidence and both accepted contract hashes. Otherwise retain the exact prior ED probability and repair. A missing/partial/malformed reply rejects the entire application; it is not an ambiguous judgment.

V3 accepts only its strict original-valid/original-invalid supported interval endpoint. V4 accepts only an eligible interval entirely below or above 0.5, using its original conservative endpoint. Intervals touching/straddling 0.5, unsupported evidence, or a verifier direction conflicting with the frozen interval retain the prior. Weights remain conditional sensitivity weights, not calibrated correctness. No new confidence blending is fitted.

An accepted original-valid judgment explicitly removes the prior repair. An accepted original-invalid judgment can add/replace a repair only when selected_value is the exact frozen-v3 repair at that coordinate, both verifier confidence and that exact candidate score are at least 0.8, and final tuple guards permit it. This restriction applies to v3 and v4. New statistical repair eligibility never expands beyond frozen v3, including v4 cases where alternative posterior winners vary.

An explicit selected_value:null abstains from NEW statistical correction. It does not invalidate an independently established prior repair. Likewise, a rejected/low-score/other selected alternative preserves the exact prior repair. Without a prior repair, accepted invalid detection plus null produces dirty detection with repair abstention. Only explicit accepted original-valid evidence can remove a legitimate prior repair. Therefore the FINAL map need not be a literal subset of frozen v3: prior fallback values absent/replaced in unverified v3 remain possible and must be identified separately in the audit.

## Safety and ED/EC coherence

The source prior must already have every repair inside its detection mask; incompatible input is rejected rather than silently normalized. Apply intended correction actions simultaneously atop that prior. Execute accepted rules only with the existing sandbox. On each changed row, compare the entire resulting tuple against the PRIOR repaired tuple, including untouched prior repairs. A newly failing multi-column rule or new accepted-rule runtime failure rolls back every statistical correction action in that row to exact prior repairs. No prior-restored constraint can regress or trigger the frozen implementation's assertion-only corner case. Single-column violations remain evidence and do not alone constitute the multi-rule veto.

Rollback retains accepted dirty ED evidence. If rollback restores a prior repair at a coordinate whose accepted original-valid conclusion had pruned ED, restore its exact prior ED probability too. This coherence rollback is disclosed; it preserves repairs inside the detection mask. Unsupported coordinates retain prior ED and EC exactly. A final independent assertion checks guard preservation and ED/EC inclusion; it is not the rollback mechanism.

## Immutable outputs and limits

Application requires complete independent judgments bound to the derived request. It freezes its exact request, reply, source inputs, protocol/implementation hashes, standard Prediction JSON, per-cell actions and per-row guard audit under a NEW output directory. No differing completed artifact is overwritten. Preparation/application do not queue models or evaluate accuracy. This is a standalone verification processor, not a standard LoopConfig payload or closed-loop experiment. An evaluator-compatible separate export may expose only its frozen prediction and unchanged source baselines; export performs no new inference.

Synthetic checks cover interval/score bounds, strict 0.5 boundaries, missing and ambiguous acceptance, assumption rejection, explicit null, exact frozen-map restriction, prior preservation, original-valid removal, multi-rule/runtime veto, simultaneous rollback, prior-restored constraints, ED/EC coherence, incomplete replies, hash mutation and immutable publication. This policy makes no effectiveness claim. Frozen hypotheses may be wrong, verifier judgments may share model errors, and reviewed coordinates are restricted to each original frozen bundle's coverage.
